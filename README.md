# Feetnessy

Личный дневник тренировок: React + TypeScript + Vite, IndexedDB (Dexie), устанавливаемое PWA. Без аккаунта, сервера данных, календарного расписания и отметок отдельных подходов. Тренировки идут по очереди, после последней — снова первая.

**Реальные тренировки пользователя пока не внесены.** Приложение начинает с пустого состояния: создайте программу, тренировки, упражнения и подходы в редакторе либо импортируйте свою резервную копию. Вымышленные тренировки не выдаются за реальные.

## Описания и история

- В «Программы → Редактировать» у тренировки и каждого упражнения есть необязательное многострочное описание: например, разминка, техника или отдых. Оно видно на экране тренировки.
- При завершении описания сохраняются вместе с результатом. Изменение программы не меняет старые описания в истории.
- Чтобы удалить одну тренировку из истории, откройте её в разделе «История», нажмите «Удалить из истории» и подтвердите. Очередь тренировок, программа и черновики не изменятся. Это не отмена выполнения; вернуть удалённую запись можно только восстановлением ранее сохранённой копии.
- Старые данные и резервные копии без описаний поддерживаются без очистки или переустановки приложения. Формат остаётся версии 1; добавлены необязательные строковые поля `description` у тренировки/упражнения и `workoutDescription` у записи истории.

## Запуск и проверки

Нужны Node.js 22.12+ и npm. Команды из корня проекта:

```sh
npm ci
npm run dev
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:pwa
npm run preview
```

- Разработка: `http://localhost:5173`; сервер слушает `0.0.0.0` и не подбирает другой порт при занятом 5173.
- Preview готовой сборки: `http://localhost:4173`, также строгий порт. Перед запуском выполните `npm run build`.
- `npm test` запускает только `src/**/*.test.ts`; Playwright запускается отдельно командой `npm run test:e2e`.
- `npm run test:pwa` собирает production-версию и проверяет manifest, service worker и полный офлайн-сценарий на порту 4173. Это отдельная проверка, не замена приёмки на настоящем Android.
- Для телефона в той же Wi-Fi-сети можно открыть `http://<IP-компьютера>:5173` (разрешите порт в брандмауэре). Это лишь проверка обычной веб-страницы: **LAN HTTP не даёт service worker, установки PWA и гарантированного офлайна**. `localhost` — исключение только на том устройстве, которому он принадлежит. Некоторые защищённые браузерные API по LAN HTTP также недоступны.

## Установка и офлайн

Опубликуйте содержимое `dist/` на статическом хостинге **с HTTPS в корне домена**. Настройка рассчитана на `/`, не на подпапку. Для адресов приложения хостинг должен возвращать `index.html`; не заменяйте им отсутствующие JS-файлы. Service worker (`sw.js`) желательно отдавать с перепроверкой свежести, а хешированные ресурсы — с длительным кэшированием.

Откройте HTTPS-адрес онлайн в Chrome на Android, дождитесь загрузки и установки service worker, затем выберите установку приложения в меню браузера. Сначала убедитесь, что страница перезагружается без сети, и только потом рассчитывайте на офлайн-работу. Статическая оболочка, JS, CSS и иконки входят в precache; холодный запуск после первой успешной установки service worker должен работать без интернета. В режиме `npm run dev` service worker намеренно выключен; проверяйте PWA на production-сборке через preview на localhost или HTTPS-хостинг.

Обновление не перезагружает открытый редактор автоматически. `registerPwa(onUpdate)` из `src/pwa.ts` уведомляет интерфейс о готовности обновления и возвращает асинхронное действие его применения. Вызывайте это действие только по явному подтверждению пользователя, после сохранения/закрытия редактора. Не добавляйте безусловный `skipWaiting` или автоматическое применение при показе уведомления. Обновление оболочки не очищает IndexedDB.

## Данные и резервные копии

Все данные находятся **в этом браузере на этом устройстве и этом origin** (протокол + домен + порт). Другой адрес, профиль или телефон — отдельное хранилище. Синхронизации нет. Если другая вкладка изменила данные, устаревшая вкладка откажется сохранять и предложит перезагрузку: изменения не объединяются автоматически, но уже сохранённая история не перезаписывается.

- IndexedDB: база `feetnessy`, версия 1, таблица `states`, ключ `id`, единственная запись `current` с полями `state` и `revision`. Ревизия проверяется внутри транзакции для защиты от устаревших сохранений.
- Состояние схемы `schemaVersion: 1`: `activeProgramId`, `programs`, `drafts`, `history`.
- JSON-копия: `{ format: "feetnessy", version: 1, exportedAt: "<ISO UTC>", data: <состояние> }`; версия формата копии отделена от версии схемы данных.
- Программа содержит упорядоченные тренировки и `nextWorkoutId`; упражнения содержат подходы `{ weightKg, reps }` (кг, допускается дробный и нулевой вес).
- Черновики привязаны к программе и тренировке; история содержит независимые снимки названий и упражнений, даты — ISO UTC.
- Состояние записывается транзакционно одной записью. Новые версии схемы требуют явных миграций и тестов сохранности данных.

Регулярно экспортируйте JSON-копию из раздела программ и сохраняйте **вне браузера**, например в файлах телефона и отдельно в облаке. Импорт заменяет текущие данные, а не объединяет их: сначала экспортируйте текущую базу, затем проверьте копию и подтвердите замену. Неверные и неподдерживаемые версии не должны менять базу.

Веса и повторы на экране тренировки сохраняются автоматически при вводе допустимых значений; незавершённое пустое/неверное значение не сохраняется. Перед завершением нажмите «Готово». Редактор всей программы работает иначе: изменения применяются по кнопке «Сохранить программу». Пока редактор открыт, переключение разделов и применение обновления заблокированы. Мгновенное принудительное завершение процесса ОС во время записи нельзя гарантированно пережить; резервная копия остаётся необходимой.

Очистка данных сайта, приватный режим, удаление браузера, потеря телефона и вытеснение хранилища могут уничтожить записи. Даже разрешение постоянного хранения не заменяет резервную копию. Кэш service worker хранит приложение, **не резервную копию тренировок**.

## Ручная приёмка на реальном Android

Это список проверок, **не заявление о том, что они уже пройдены на телефоне**. Используйте отдельную тестовую программу и сохраните копию важных данных заранее.

- [ ] Открыть HTTPS-сборку в Chrome, установить PWA; проверить название, иконку и самостоятельное окно с домашнего экрана.
- [ ] Создать программу из четырёх тренировок в редакторе; проверить порядок, переименование и удаления с подтверждением.
- [ ] Ввести дробный вес, в том числе с запятой; изменить подходы и повторы. Закрыть приложение, открыть снова и проверить черновик.
- [ ] Завершить четыре тренировки: очередь проходит 1 → 2 → 3 → 4 → 1. Двойное нажатие не создаёт дублей; перерыв и перезапуск не сдвигают очередь.
- [ ] Проверить разовые изменения и перенос в шаблон, отмену завершения, независимость истории от редактирования шаблонов.
- [ ] Переключить программы и проверить независимые очереди/черновики. Убедиться, что конфликт редактирования с черновиком требует подтверждения.
- [ ] После первой онлайн-загрузки включить авиарежим, полностью закрыть PWA и запустить с иконки. Открыть историю, изменить и завершить тренировку, перезапустить и проверить сохранение.
- [ ] Экспортировать JSON; в отдельном тестовом профиле импортировать и сверить программы, очередь, историю и черновики. Неверный файл не меняет данные.
- [ ] С открытым несохранённым редактором опубликовать новую сборку и открыть приложение онлайн. Проверить отсутствие самопроизвольной перезагрузки; сохранить изменения, явно применить обновление, сверить данные и снова проверить холодный офлайн-запуск.
- [ ] Проверить понятные ошибки при недоступном хранилище: интерфейс не должен сообщать об успешной записи, которой не было.
